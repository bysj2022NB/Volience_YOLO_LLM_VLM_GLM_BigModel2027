## 项目概述

本项目是一套面向公共场所安全值守的智能检测、分析与预警系统，产品名称为 **CivicShield／城安智警**。系统以 YOLO 本地目标检测为基础，以视觉多模态模型为辅助复核能力，覆盖图片、视频、本机摄像头和 RTSP/RTSPS 网络监控点位，可完成暴力行为识别、风险分级、证据留存、人工处置、模型训练与评估等工作。

系统采用 Electron + Vue 3 构建 Windows 桌面客户端，Flask 提供仅在本机运行的业务与算法服务。客户端包含启动与认证流程，以及工作台、图片检测、图片记录、视频检测、视频任务、实时检测、预警中心、模型评估、数据集管理、模型与训练、用户管理、个人中心、系统设置和状态展示共 14 个页面。正式界面延续已审核原型的结构与交互，视觉采用“雾白 + 石墨灰 + 雾紫”的浅色极简风，橙色和红色只用于风险语义。

内置数据集为严格的二分类 YOLO 数据集：`0 nonViolence`、`1 violence`，共 6,946 张图片、10,822 个标注框；训练集中存在 1 个无目标标签文件，这是合法的负样本，不属于损坏数据。系统内置 `yolo11n.pt`、`yolo12n.pt`、`yolo26n.pt` 和 `yolov8n.pt` 四个通用基础权重，它们只能用于迁移训练，不能直接发布为暴力检测模型或生成模拟结果。图片、视频与实时推理始终要求存在已校验、已发布的二分类业务模型。

### 核心创新点

1. **本地二分类检测**：围绕 `nonViolence` 与 `violence` 两类目标完成检测框定位、置信度计算和结果标注，基础权重与业务权重严格分离。
2. **多来源统一分析**：使用同一套模型与风险规则处理图片、视频、本机摄像头和 RTSP/RTSPS 点位，兼顾离线取证和实时值守。
3. **五级风险判定**：根据最高 `violence` 置信度划分可忽略、轻微、中等、严重和紧急；实时连续命中时上调一级，同时保留原始等级与升级原因。
4. **多路实时监控**：最多选择 9 路运行中的网络点位，自动适配单画面、双画面、四宫格或九宫格，并对每路视频独立抽帧、检测和故障隔离。
5. **完整模型生命周期**：支持权重上传、训练、停止、从原进度续训、发布、取消发布、评估和删除；训练详情实时显示 Precision、Recall、mAP、已用时间、预计剩余时间、日志和产物。
6. **多模态辅助复核**：图片、视频关键帧和预警证据均可发起视觉 AI 复核，以进度条和阶段文字反馈分析过程，并输出场景说明、风险结论、证据、局限性和处置建议。
7. **同类型模型顺序回退**：通过 LangChain 管理 OpenAI-compatible 文本与视觉模型；当前供应商失败后按优先级尝试下一同类型模型，本地 YOLO 链路不受外部 AI 故障影响。
8. **流媒体一体化管理**：集成 MediaMTX、FFmpeg、FFprobe 和 HLS.js，可将本地视频循环发布为本机 RTSP/HLS，也可接入真实网络流，并在桌面端完成测试、启停、预览和状态管理。
9. **风险处置闭环**：检测结果通过 ByteTrack 轨迹、事件去重、证据帧保存、桌面通知、AI 复核和人工处置形成“检测—研判—预警—处置—审计”闭环。
10. **本地化安全设计**：采用 JWT、Argon2、管理员/普通用户权限、SQLite、敏感信息脱敏、受控文件路径和 Electron 白名单 IPC，关键操作均可审计追踪。

### 应用场景

- **商业综合体监测**：用于商场中庭、出入口和步行街区等客流密集区域的冲突行为识别与风险留痕。
- **交通枢纽与地铁站厅**：辅助值守人员关注站厅、闸机和换乘区域中的暴力行为或异常聚集。
- **校园与文体场馆**：面向校园广场、体育场馆、看台和公共活动区域提供异常行为预警。
- **街区与公共服务区域**：对广场、步行区和公共服务大厅等开放空间进行离线或实时分析。
- **安防指挥与值守中心**：统一管理图片、视频、监控点位、预警、模型和处置记录，为人工决策提供证据支持。

## 技术架构

### 整体架构设计

系统由 Electron 桌面客户端、Flask 本地服务、本地视觉算法、外部多模态 AI、流媒体服务和运行数据层组成。开发阶段通过两个终端分别启动后端与客户端，不制作 EXE 安装包。Flask、MediaMTX 控制接口以及 RTSP/HLS/WebRTC 服务均按本机应用场景限制在回环地址，避免直接向局域网暴露。

```text
┌────────────────────────────────────────────────────────────────┐
│ Electron 桌面客户端                                            │
│ 主进程：窗口、文件选择、摄像头权限、系统通知、生命周期          │
│ Preload：经过白名单约束的 IPC                                  │
│ Vue 渲染进程：14 个页面、路由权限、Pinia、HLS 播放与交互反馈     │
└───────────────────────────────┬────────────────────────────────┘
                                │ REST / WebSocket
┌───────────────────────────────▼────────────────────────────────┐
│ Flask 本地后端（127.0.0.1:5020，统一前缀 /api/v1）             │
│ 认证权限 │ 业务接口 │ 异步任务 │ 统一响应 │ 审计与日志           │
├───────────────────┬────────────────────┬───────────────────────┤
│ YOLO + OpenCV     │ LangChain          │ MediaMTX + FFmpeg     │
│ ByteTrack         │ OpenAI-compatible  │ RTSP/RTSPS + HLS      │
│ 检测、跟踪、标注  │ 文本/视觉顺序回退  │ 本地视频循环推流      │
└───────────────────┴────────────────────┴───────────────────────┘
                                │
┌───────────────────────────────▼────────────────────────────────┐
│ SQLite + 根目录 runtime                                        │
│ 数据库、模型、训练、评估、上传、输出、日志、缓存与媒体服务状态  │
└────────────────────────────────────────────────────────────────┘
```

客户端通过 REST API 完成登录、查询、文件上传和业务操作；训练任务通过 `/ws/tasks/{task_id}` 推送指标和日志，实时检测通过 `/ws/realtime/{session_id}` 交换检测帧、归一化检测框、轨迹、预警和视频源状态。训练、视频检测和模型评估使用后台任务运行，页面通过进度状态与轮询/WebSocket 获取结果，避免阻塞 Flask 请求线程。

本机摄像头由 Electron 授权后在客户端流畅预览，只按用户设置的检测间隔向后端发送 JPEG 帧；网络点位由 MediaMTX 统一输出，本地后端并行读取流进行检测，客户端通过 HLS 播放并提供失败重连。所有检测仍以 YOLO 原始结果为事实基础，视觉 AI 复核单独存储，不静默修改原风险结论。

### 技术栈详解

#### 前端技术栈

- **桌面容器**：Electron 44，负责桌面窗口、文件与目录选择、摄像头权限、系统通知及有限窗口控制。
- **核心框架**：Vue 3.5 + TypeScript 5.9，使用由已批准原型同步生成的页面组件，并通过运行时桥接真实业务数据。
- **UI 与图标**：Element Plus 2.11、Lucide Vue Next，并使用统一语义化主题变量维护雾白、石墨灰、雾紫及风险状态色。
- **状态与路由**：Pinia 3.0、Vue Router 4.5，维护登录态、JWT、用户角色、页面权限和导航状态。
- **网络与播放**：Axios 1.11 统一封装 `/api/v1` 请求、令牌刷新和错误提示；HLS.js 1.6 负责 RTSP 点位转换后的桌面端播放与重连。
- **工程与质量**：electron-vite 4、Vite 7、vue-tsc、ESLint、Vitest 和 Playwright，覆盖类型、规范、页面、真实后端及 Electron 启动验证。
- **安全边界**：渲染进程关闭 Node 集成并启用上下文隔离、沙箱和 Web 安全；Preload 仅暴露图片/视频/数据集/模型选择、安全路径打开、通知和窗口控制。

#### 后端技术栈

- **核心框架**：Python 3.13、Flask 3.1、Flask-SQLAlchemy、Flask-Migrate、Alembic 和 Flask-Sock。
- **数据存储**：SQLite 3，采用 DELETE journal 模式并配置短事务与超时；保存用户、会话、数据集、模型、任务、检测、预警、点位、AI 配置和审计记录。
- **身份认证**：Flask-JWT-Extended + Argon2；支持账号密码登录、短信验证码登录、短信重置密码、刷新令牌轮换和退出撤销。
- **视觉算法**：Ultralytics YOLO 8.4、PyTorch、OpenCV、NumPy 和 Pillow，支持 CPU/CUDA 推理、训练、跟踪、CLAHE 增强和检测结果绘制。
- **视频与流媒体**：FFmpeg、FFprobe、MediaMTX 和 HLS，用于媒体探测、抽帧、H.264 输出、本地循环推流和网络点位管理。
- **多模态 AI**：`langchain-core`、`langchain-openai`，通过 OpenAI-compatible 接口执行文本/视觉模型测试、调用、结构化结果校验与顺序回退。
- **报告与安全**：python-docx 生成图片检测报告；cryptography 加密本地敏感配置；路径服务、日志脱敏和审计服务保护运行数据。
- **短信服务**：沿用阿里云市场短信接口的 `APPCODE` 鉴权和表单字段，通过 `.env` 配置凭据、模板与超时，并实现 5 分钟有效期、60 秒冷却和频率限制。

## 核心功能模块

1. **用户认证与个人中心**：支持用户名、密码直接注册，手机号可在登录后绑定或修改且保持唯一；已绑定手机号可用于短信登录和短信重置密码。验证码按钮提供“发送中”、成功倒计时、失败恢复和重复点击保护。JWT 支持访问令牌、刷新轮换和退出撤销。个人中心可维护真实姓名、手机、邮箱和单位信息。开发种子管理员为 `admin / 123456`，首次使用应修改密码。

2. **用户管理**：管理员可按关键词、角色和状态筛选用户，执行新增、编辑、启用、禁用、重置密码、单条删除和批量操作。系统保护当前登录管理员及最后一个有效管理员，避免误操作导致管理权限丢失；敏感操作进入审计日志。

3. **数据集管理**：首次启动扫描并注册 `dataset/data.yaml`，显示 6,946 张图片、10,822 个标注框和二分类信息。管理员可导入包含 `data.yaml` 的 ZIP 数据集、切换当前查看项、重新校验、启停和删除；校验覆盖 YAML、目录划分、图片/标签对应关系、类别编号、越界路径、符号链接和无目标标签。重新校验后保持当前数据集选择，不跳回内置数据集。

4. **模型与训练管理**：支持上传 `.pt` 业务权重或基于数据集和基础权重新建训练任务，可配置任务名称、设备、Epoch、图像尺寸、Batch、优化器、学习率等参数。页面实时显示进度、Precision、Recall、mAP50、损失、已训练时间、预计剩余时间、日志和产物。停止任务时保存 `resume.pt`；续训复用原任务记录和原进度，优先恢复完整优化器状态，历史精简检查点则保留模型权重并重建优化器继续剩余轮次。完成的二分类模型可发布、取消发布和参与评估。

5. **图片检测与图片记录**：用户选择图片后先查看原图，提交任务后才展示检测结果。后端执行 CLAHE 增强与 YOLO 推理，返回标注图、目标列表、置信度、裁剪图、本地文字摘要和基于真实检测值计算的风险等级。视觉 AI 复核以进度条展示准备证据、调用模型和形成结论等阶段，结果包含明确结论、场景描述、证据、置信依据、局限性和处置建议。离开检测页后清空当前结果；图片记录页展示缩略图，并提供丰富详情、AI 复核和 Word 报告导出。

6. **视频检测与视频任务**：支持手动输入采样频率和关键帧间隔，视频上传后以异步任务反馈进度。完成后播放兼容桌面端的 H.264 标注视频，并展示关键帧缩略图、时间戳、YOLO 检测框与文字说明；任意横竖比例的视频和图片均使用完整适配方式显示。关键帧可单独发起 AI 复核。离开视频检测页后恢复初始状态；视频任务页提供缩略图、任务详情、标注视频、全部关键帧、逐帧检测详情和历史 AI 结果。

7. **实时检测**：支持本机摄像头和 RTSP 多点位两种模式。本机摄像头保持客户端本地预览，只按设置间隔发送检测帧，停止后释放媒体轨道并恢复初始画面。网络模式展示全部运行点位，用户最多选择 9 路；客户端通过 HLS 显示实际画面，后端并行抽帧检测并推送归一化检测框、轨迹和事件。各路支持独立状态、失败重连和故障隔离，不以模拟场景替代无法播放的真实视频。

8. **网络监控点位与流媒体管理**：系统设置页可检测和启停 MediaMTX 服务，并管理本地视频或真实 RTSP/RTSPS 点位。本地 MP4、MOV、MKV、AVI、WebM 等文件经 FFprobe 校验后由 FFmpeg 循环发布，文件选择通过 Electron 原生对话框完成。点位支持创建、搜索、筛选、测试、开启、关闭、编辑、详情和软删除；实时检测只使用已成功运行并具有播放地址的点位。

9. **预警中心与通知中心**：中等及以上风险默认生成预警，实时事件按点位、轨迹、类别和时间窗口去重。预警列表支持关键词、来源、等级、AI 状态、处置状态与时间筛选，筛选条件不会被后台刷新覆盖；证据缩略图通过鉴权文件接口加载。详情弹窗展示 YOLO 证据、对象列表、AI 结果和处置历史，可执行解决、误报、忽略、通知现场、报警或重新打开。批量删除允许处理任意状态的所选预警，采用软删除并写入审计。通知中心展示预警和后台任务消息，侧栏数字只统计待处理预警。

10. **模型评估**：用户可选择业务模型和数据集创建异步评估任务，系统先校验类别与权重维度。完成后展示整体与分类 Precision、Recall、mAP50、mAP50-95、PR 曲线、混淆矩阵以及 GT/预测对比图。点击历史记录可切换上方全部指标与图表；详情弹窗展示任务参数、环境信息、分类指标和可用过程图，历史记录可独立删除。

11. **多模态 AI 模型管理**：系统设置页支持添加、编辑、测试、启停、排序和删除 OpenAI-compatible 文本或视觉模型，可配置 Base URL、模型名、API Key、超时和重试。测试期间“最近测试”列显示加载状态，操作按钮提供清晰字号和悬浮说明。调用时只在同类型启用模型之间顺序回退；AI 全部失败时保留本地 YOLO 结果并显示可理解的错误，不伪造复核结论。

12. **系统设置、安全与运行状态**：工作台与设置页展示后端、数据库、Python、PyTorch、CUDA/GPU、FFmpeg、MediaMTX、磁盘和运行目录状态，并管理检测阈值、IoU、风险规则、实时采样、数据保留和桌面通知。接口统一采用 `/api/v1`、UUID、UTC+8 ISO 8601、标准分页及 `{code, message, data, request_id}` 响应。密码使用 Argon2，短信 AppCode 与模板从 `.env` 读取，AI/RTSP 凭据加密保存；文件上传、下载和 IPC 路径均执行越界校验，删除、启停、发布、配置与处置操作保留审计记录。
